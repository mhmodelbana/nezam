# Supabase setup

The static app now uses Supabase Auth and the `app_state` table as its shared
database. The database starts empty; browser Local Storage is not imported.

## 1. Create the database objects

Open the Supabase project's SQL Editor and run [`supabase/setup.sql`](./supabase/setup.sql).
The script enables row-level security and creates the admin-only application
state table plus student-scoped portal and trip-registration functions.

## 2. Create the first administrator

1. In **Authentication → Users**, create an administrator user with an email
   address and password.
2. Copy the user's Auth UUID.
3. Run this query in the SQL Editor, replacing the UUID:

   ```sql
   insert into public.profiles (user_id, role, student_id)
   values ('AUTH-USER-UUID', 'admin', null);
   ```

Use that email and password on the login page. There is no default or
hard-coded administrator password.

## 3. Deploy student account management

Deploy the Edge Function from the repository root using the Supabase CLI:

```text
supabase functions deploy manage-student-auth
```

Supabase supplies the function's project URL and service-role key as server
environment variables. The service-role key is used only inside the function;
never copy it into a browser file. The function checks the caller's admin role
before creating or resetting a student Auth account.

## 4. Publish the static app

`supabase-config.js` contains the project's URL and **publishable** key. A
publishable key is intended for browser use; the row-level security policies
and Auth roles protect the data. Host the pages over HTTPS (or localhost for
development), then log in with the administrator account.

New student accounts use their `VT-0001` code and a temporary password
generated by the admin UI. The generated Auth email is internal and does not
receive mail; administrators reset student passwords from the student list.
Students must change the temporary password on first login.

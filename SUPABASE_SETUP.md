# Supabase setup

The application stores business data in Supabase tables: `students`, `terms`,
`subscriptions`, `trip_schedules`, and `trip_requests`. Supabase Auth manages
administrator and student accounts. The browser does not use a local data
store; Supabase Auth may persist the signed-in session in the browser.

## 1. Create the database objects

In the Supabase SQL Editor, run these scripts in order:

1. [`supabase/setup.sql`](./supabase/setup.sql) creates the account profiles
   and administrator-role check.
2. [`supabase/tables.sql`](./supabase/tables.sql) creates the business tables,
   row-level security policies, and student-only portal actions.

The scripts are safe to run again for the current schema. Existing rows are
not imported from browser storage or the older `app_state` table; import any
legacy records into the matching Supabase tables before relying on them.

## 2. Create the first administrator

1. In **Authentication → Users**, create an administrator user.
2. Copy the user's Auth UUID.
3. Run this query in the SQL Editor, replacing the UUID:

   ```sql
   insert into public.profiles (user_id, role, student_id)
   values ('AUTH-USER-UUID', 'admin', null);
   ```

Use that email and password on the login page. There is no default or
hard-coded administrator password.

## 3. Deploy student account management

Deploy the Edge Function from the repository root using the Supabase CLI:

```text
supabase functions deploy manage-student-auth
```

Supabase provides the function URL and service-role key as server environment
variables. The service-role key is used only inside the function; never put it
in a browser file. The function verifies the caller's administrator role
before creating or resetting a student Auth account.

New student accounts use their `VT-0001` code and a temporary password
generated by the administrator UI. The generated Auth email is internal and
does not receive mail; administrators reset student passwords from the student
list. Students must change the temporary password on first login.

## 4. Publish the static app

`supabase-config.js` contains the project URL and publishable key. A
publishable key is intended for browser use; row-level security and Auth roles
protect database access. Host the pages over HTTPS (or localhost during
development). Changes made in the administration and student portals are
written to Supabase and are shared across sessions.
